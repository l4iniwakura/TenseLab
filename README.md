# TenseLab

Ежедневная практика английских времён: устный дрилл, перевод, таблицы и локальный прогресс.

## Версии сайта

Один пакет GitHub Pages содержит основную и тестовую сборки приложения, лендинг и архивную версию:

| Адрес | Назначение | Исходники |
| --- | --- | --- |
| `/TenseLab/` | Выбор версии | `index.html` |
| `/TenseLab/landing/` | Лендинг | `landing/` |
| `/TenseLab/app/` | Стабильное React-приложение | `main:frontend/` |
| `/TenseLab/demo/` | Тестовое React-приложение | `develop:frontend/` |
| `/TenseLab/pr-<номер>/` | Предпросмотр открытого MR | Head-коммит ветки MR |
| `/TenseLab/old/` | Архивная HTML-версия с исходной механикой | `old/index.html` |

## Разработка

Нужны Node.js 22.12+ и npm. Из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Открой адрес, напечатанный Vite, с путём `/TenseLab/app/`. Все учебные данные поставляются в сборке; backend, аккаунты и внешние API не используются. Озвучка использует голоса браузера/ОС; наличие английского офлайн-голоса зависит от устройства.

```sh
npm run format:check
npm run lint
npm test
npm run build
npm run test:e2e
```

Локально браузерные тесты используют установленный Chrome. В CI они используют Chromium, устанавливаемый командой `npx playwright install --with-deps chromium`. Тесты проверяют обе ширины экрана, сценарии тренировки, сохранение темы, старые данные, озвучку и офлайн-перезагрузку. В тесте миграции проверяются все 7 344 сочетания генератора по оригинальному HTML.

## Архитектура фронтенда

- `src/domain/` — типы, учебный каталог и чистые функции генерации/сравнения.
- `src/stores/` — MobX-stores дрилла, перевода и прогресса, объединённые RootStore и переданные через React Context.
- `src/features/` — четыре раздела интерфейса.
- `src/storage/` — проверка и сохранение данных в localStorage.
- `src/app/` и `src/components/` — оболочка, темы, CSS Modules и общие элементы управления.

Разделы имеют hash-ссылки: `#drill`, `#translation`, `#reference`, `#progress`. Они работают на статическом хостинге, при обновлении страницы и навигации назад/вперёд.

В «Карте времён» можно выбрать любое сочетание времён нажатием на ячейки и нажать «Начать дрилл». Каждый выбранный элемент добавляет три формы: утверждение, отрицание и вопрос. Свой набор работает с обычным и случайным порядком, автотемпом и новой фразой. Из дрилла можно вернуться к выбору или переключиться на готовую таблицу. Набор сохраняется при переходах между разделами в текущей сессии; перезагрузка страницы сбрасывает его. Повторное нажатие на ячейку снимает выбор. Переключатель типа предложения в карте меняет только примеры.

Прогресс и тема разделены по окружениям: `tenselab:<channel>:progress:v2` и `tenselab:<channel>:theme`, где `<channel>` — `app`, `demo` или `pr-<номер>`. Обычные обновления приложения сохраняют эти ключи. При первом запуске новая схема автоматически переносит данные своего `progress:v1`, предварительно сохраняя точную резервную копию; исходный ключ не удаляется. Повреждённые записи и неизвестные версии защищены от автоматической перезаписи. В случае изменения данных другой вкладкой сохранение из устаревшей вкладки блокируется: новые результаты этой вкладки остаются в памяти и не перезаписывают сохранённую статистику.

Страница «Мой прогресс» содержит общие итоги, календарь активности и статистику выбранного дня. Пользовательского сброса, импорта и экспорта статистики в интерфейсе нет. Неиспользуемый API импорта, экспорта и сброса удалён. Автоматическая миграция и резервное копирование перед ней сохраняются: копии находятся в ключах `:backup:<ISO-время>:<UUID>`, исходные данные не удаляются. Старый общий ключ HTML-версии `tenselab-progress-v1` автоматически не переносится. Очистка данных сайта удаляет и локальный прогресс, и резервные копии.

Статистика отдельно показывает все самооценённые переводы, ответы «Получилось» и полностью завершённые дриллы. Дрилл засчитывается после перехода «Следующая форма» с каждой карточки набора, включая последнюю (вручную или в авторежиме). Прыжок к последней карточке, перезапуск и смена набора/порядка не дают завершения. Это объём практики, а не оценка произношения или уровня языка. Дневная история сохраняется по местной дате в момент события; смена часового пояса не переносит старые записи. Календарь показывает последние 12 календарных месяцев; на телефоне можно выбирать месяц. При миграции сохраняются общие итоги и единственный доступный дневной счётчик; неизвестная правильность этого дня помечается, отсутствующая история не выдумывается. Все 7 344 исходных сочетания сохранены буквально, включая известные лингвистические ограничения первоначального генератора: корректировку учебного контента следует делать отдельным изменением.

## GitHub Pages

Лендинг по taste skill находится в `landing/` и публикуется в `/TenseLab/landing/`. В корне сайта — страница выбора версии. Инструкция по настройке Pages и адресов: [landing/README.md](landing/README.md).

Workflow находится в `.github/workflows/frontend.yml`. Push в `main` или `develop`, открытие MR и новые коммиты публикуют общий пакет: `main` в `/TenseLab/app/`, `develop` в `/TenseLab/demo/`, открытые MR из этого репозитория в `/TenseLab/pr-<номер>/`. Закрытие MR удаляет его предпросмотр при следующей публикации. Ссылки находятся в summary задачи deploy, SHA сборки — в `pr-<номер>/preview.json`. Ошибка отдельной тестовой ветки не блокирует сборку остальных версий.

В Settings → Pages выбери Source: **GitHub Actions**. В environment `github-pages` разреши `main`, `develop` и `refs/pull/*/merge`. Новый workflow должен находиться в обеих ветках до первого запуска: старый workflow из main не сохраняет предпросмотры. Старые ветки MR нужно обновить из develop для поддержки канала `pr-<номер>`.

Service worker app/demo ограничен каталогом версии и использует отдельный cacheId. У предпросмотров отдельный localStorage и отключённый service worker, чтобы обновление страницы показывало актуальную сборку. Подробности — в [docs/deployment.md](docs/deployment.md).

## Продуктовые документы

Исходная архитектура находится в `docs/`. `PRODUCT.md` фиксирует принятые ограничения, `DESIGN.md` — сохраняемую визуальную систему. Многомодульный backend на Java/Spring планируется отдельным этапом.

## Локализация

Интерфейс поддерживает Русский, English и Deutsch. Язык выбирается в общей шапке; выбор сохраняется отдельно для app/demo/PR. Задания на перевод пока русские, изучаемый язык — английский. Пояснения в карте и к формулам доступны на всех трёх языках. Устройство продолжает хранить прогресс и тему независимо от языка интерфейса. Структура ресурсов, fallback и правила расширения: [docs/localization.md](docs/localization.md).

В каждой ячейке карты есть отдельная кнопка «Примеры». Она открывает жизненные ситуации выбранного времени: две ситуации по два примера с переводом и объяснением, плюс раскрываемое сравнение с близким временем. Одновременно показана одна ситуация одного времени; выбор для дрилла не меняется. Для возврата используй кнопку закрытия или Escape.


## Неодушевлённые подлежащие (#16)

Обычный дрилл и существующий фильтр лица в переводах включают `it`, `the computer`, `the train`, `the phone`. Новые глаголы соединяются только с проверенными подлежащими: обработка данных компьютером, поездка поезда по маршруту и зарядка телефона на столе. Местоимение `it` использует эти же контексты. Для новых подлежащих учитываются третье лицо единственного числа и русский род; новые совершённые действия имеют отдельные русские формы. Все 12 времён и три формы доступны через прежние фильтры и пользовательские наборы. Полный пул содержит 7 560 сочетаний; исходные 7 344 по-прежнему проверяются буквально по архивной версии.
