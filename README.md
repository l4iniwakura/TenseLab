# TenseLab

Ежедневная практика английских времён: устный дрилл, перевод, таблицы и локальный прогресс.

## Версии сайта

Один пакет GitHub Pages содержит основную и тестовую сборки приложения, лендинг и архивную версию:

| Адрес | Назначение | Исходники |
| --- | --- | --- |
| `/TenseLab/` | Выбор версии | `index.html` |
| `/TenseLab/landing/` | Лендинг | `landing/` |
| `/TenseLab/app/` | Стабильное React-приложение | `main:frontend/` |
| `/TenseLab/demo/` | Тестовое React-приложение | `develop:frontend/` |
| `/TenseLab/old/` | Исходная HTML-версия без изменений | `old/index.html` |

## Разработка

Нужны Node.js 22.12+ и npm. Из корня репозитория:

```sh
cd frontend
npm ci
npm run dev
```

Открой адрес, напечатанный Vite, с путём `/TenseLab/app/`. Все учебные данные поставляются в сборке; backend, аккаунты и внешние API не используются. Озвучка использует голоса браузера/ОС; наличие английского офлайн-голоса зависит от устройства.

```sh
npm run format:check
npm run lint
npm test
npm run build
npm run test:e2e
```

Локально браузерные тесты используют установленный Chrome. В CI они используют Chromium, устанавливаемый командой `npx playwright install --with-deps chromium`. Тесты проверяют обе ширины экрана, сценарии тренировки, сохранение темы, старые данные, озвучку и офлайн-перезагрузку. В тесте миграции проверяются все 7 344 сочетания генератора по оригинальному HTML.

## Архитектура фронтенда

- `src/domain/` — типы, неизменённый учебный каталог и чистые функции генерации/сравнения.
- `src/stores/` — MobX-stores дрилла, перевода и прогресса, объединённые RootStore и переданные через React Context.
- `src/features/` — четыре раздела интерфейса.
- `src/storage/` — проверка и сохранение данных в localStorage.
- `src/app/` и `src/components/` — оболочка, темы, CSS Modules и общие элементы управления.

Разделы имеют hash-ссылки: `#drill`, `#translation`, `#reference`, `#progress`. Они работают на статическом хостинге, при обновлении страницы и навигации назад/вперёд.

Прогресс и тема разделены по окружениям: `tenselab:app:progress:v1` и `tenselab:app:theme` для основной версии, `tenselab:demo:progress:v1` и `tenselab:demo:theme` для тестовой. Старые общие ключи остаются нетронутыми, но автоматически не читаются.

Статистика отражает самооценку перевода. Устный дрилл не измеряет произношение и не увеличивает её. Генерируемые предложения сохранены буквально, включая известные лингвистические ограничения первоначального генератора: корректировку учебного контента следует делать отдельным изменением.

## GitHub Pages

Лендинг по taste skill находится в `landing/` и публикуется в `/TenseLab/landing/`. В корне сайта — страница выбора версии. Инструкция по настройке Pages и адресов: [landing/README.md](landing/README.md).

Workflow находится в `.github/workflows/frontend.yml`: это YAML-конфигурация GitHub Actions. Pull request запускает проверки, push в `main` или `develop` — сборку обеих веток и публикацию общего пакета: `main` в `/TenseLab/app/`, `develop` в `/TenseLab/demo/`. Если проверка любой версии падает, публикация не выполняется.

В Settings → Pages выбери Source: **GitHub Actions**. В environment `github-pages` разреши публикацию из обеих веток. Workflow и поддержка `VITE_APP_CHANNEL` должны находиться в обеих ветках до первого запуска.

Service worker каждой версии ограничен её каталогом и использует отдельный cacheId. Подробности настройки, локальной сборки и упаковки — в [docs/deployment.md](docs/deployment.md).

## Продуктовые документы

Исходная архитектура находится в `docs/`. `PRODUCT.md` фиксирует принятые ограничения, `DESIGN.md` — сохраняемую визуальную систему. Многомодульный backend на Java/Spring планируется отдельным этапом.
