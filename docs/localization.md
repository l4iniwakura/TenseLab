# Frontend localization

UI resources live in `frontend/src/locales/ui/{ru,en,de}.json`. `I18nStore` registers supported locales with their native names as accessible labels and tooltips on the flag buttons. Flags represent the current packs (Russian, British English, German), not all countries using a language. All resources are statically imported into the app bundle and included in the existing service-worker precache; switching languages needs no network request.

Call `i18n.t('stable.semantic.key', { count, ...values })` from observed React components or stores. Strings interpolate named `{parameters}` as plain text. Never concatenate translated sentence fragments or render translations as HTML. Use `i18n.number` and `i18n.date` for display, and `Intl.PluralRules` plural maps (`one`, `few`, `many`, `other` as needed) for quantities. Dates stored for study-day boundaries continue to use `localDay`, not display formatting.

The browser language list is considered in order, including regional variants. The default is Russian (`ru`). An explicit choice overrides browser settings and is stored under `tenselab:${channel}:uiLocale` (app/demo/PR isolated). Denied storage leaves the choice active for the current session. The shell updates the document language immediately. Missing keys fall back to Russian, then to the stable key; development mode warns. Unit tests enforce identical keys and parameter names, nonempty values and all plural categories in every resource.

To add a UI language, add a resource file and register its import/resource entry and native name in `I18nStore`. Run the resource contract tests and check all screens on mobile, including long accessible labels. No changes to exercises, domain IDs or answer validation are needed.

Translation exercises use the Russian-to-English pack in `locales/content/ru/` (lexical catalog and Russian sentence generator). The `domain/catalog.ts` facade preserves existing engine imports. `contentLocale = ru` and `targetLanguage = en` are independent of `uiLocale`. The shell explains the exercise language in the selected UI language. UI switching does not recreate stores or change filters, answers, retry queues, rounds, theme or statistics. Additional exercise packs require their own content selection/generator contract.

Reference explanations have separate ru/en/de content resources in `locales/content/{locale}/reference.json`. They follow the displayed UI language as requested, independently of translation exercises. This covers map descriptions, formula help, table notes and German example translations; the English table shows its originals without redundant translation lines.

Everyday usage examples are structured separately: `domain/usage-originals.json` holds immutable English originals with stable tense, situation and example IDs; `locales/content/{locale}/usage.json` holds contexts, translations, explanations, contrast pairs and optional notes. The content loaders have Russian fallback. Each tense has two distinct situations with two examples each and a contrast pair. To add content, update every pack and run the content-contract tests, then review the meaning, translations and temporal context. Adding a UI locale alone does not change the exercise engine.

English originals use `lang="en"`; explanations and translations use their content language. All UI and reference packs are bundled for offline use. The map opens one lesson at a time, shows one situation at a time and keeps contrasts collapsed until requested. Viewing content never changes the selected drill tenses. Escape or the close button restores focus to the originating map control.
